# Elapsed-time Heat Coloring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tint the elapsed-time field of each `shrike doctor` finding row on a duration "heat" ramp so a long-running process visibly explains its time-weighted severity.

**Architecture:** A pure `ageHeatLevel(d) → 0–3` helper, a dedicated `AgeHeat [4]lipgloss.Style` warm ramp in the theme, and a one-line render tweak in `renderListBody` (pad the age first, then style it).

**Tech Stack:** Go 1.26, Bubble Tea, lipgloss, standard `go test`.

**Spec:** `docs/superpowers/specs/2026-06-14-age-heat-design.md`

**Conventions for every commit:** run `gofmt`/`goimports`, then `go test ./...`. Commit messages use `feat:` / `test:` / `docs:`. No `Co-Authored-By` trailer (attribution disabled globally for this repo).

**Key facts:** `internal/tui/style/theme.go` — `Theme` is a struct; `DefaultTheme()` returns a literal; `FromConfig(high, medium, low)` calls `DefaultTheme()` then overrides severity (so it inherits anything added to `DefaultTheme`). In `internal/tui/doctor/view.go`, `renderListBody` builds each row's `data` with one `fmt.Sprintf` where the age is a `%-7s` field; `killed := isFindingKilled(f, m.KilledPIDs)` is computed earlier in the loop; `time` is already imported. `formatElapsedShort(sec)` returns `"8d 0h"` for 8 days.

Add this function (e.g. right after `formatElapsedShort`):

```go
// ageHeatLevel maps a process's elapsed runtime to a 0–3 "heat" level used to
// tint the age field: 0 < 12h, 1 ≥ 12h, 2 ≥ 2d, 3 ≥ 7d.
func ageHeatLevel(d time.Duration) int {
	switch {
	case d >= 7*24*time.Hour:
		return 3
	case d >= 2*24*time.Hour:
		return 2
	case d >= 12*time.Hour:
		return 1
	default:
		return 0
	}
}
```

- [ ] **Step 4: Tint the age field in `renderListBody`**

The row's `data` is currently built as:

```go
		data := fmt.Sprintf("%-30s  PID %-6d %s %s%.1f%% CPU · %-7s · %-7s %s",
			cmdLabel, f.Process.PID, bar, cpuPrefix, cpu, rssLabel,
			formatElapsedShort(int64(f.Process.ElapsedTime.Seconds())), sev)
```

Replace that whole statement with (pre-pad-then-style the age, swap its `%-7s` for `%s`):

```go
		// Pad the age to width first, THEN tint it — styling a %-Ns field would
		// inflate the byte count with ANSI escapes and break column alignment.
		ageStr := fmt.Sprintf("%-7s", formatElapsedShort(int64(f.Process.ElapsedTime.Seconds())))
		if !killed {
			ageStr = t.AgeHeat[ageHeatLevel(f.Process.ElapsedTime)].Render(ageStr)
		}
		data := fmt.Sprintf("%-30s  PID %-6d %s %s%.1f%% CPU · %-7s · %s %s",
			cmdLabel, f.Process.PID, bar, cpuPrefix, cpu, rssLabel, ageStr, sev)
```

(The `rssLabel` stays `%-7s`; only the age field becomes `%s` carrying the pre-styled `ageStr`.
`killed` is already in scope from earlier in the loop.)

## Self-Review notes (resolved during planning)

- **Spec coverage:** `AgeHeat` theme ramp (T1), `ageHeatLevel` + render tint (T2), changelog + verify incl. golangci-lint (T3). All spec sections mapped.
- **Alignment safety:** age is padded to 7 chars *before* styling, then embedded as `%s`; `rssLabel` keeps its `%-7s`. T2 Step 6's full-suite race run is the alignment regression guard.
- **Killed rows:** the tint is gated on `!killed`, so a strikethrough row stays uniformly restyled (mirrors the `⏸ paused` tag).
- **Test reality:** lipgloss strips colour in the non-TTY test env, so `ageHeatLevel` (table-tested) is the real behavior check; the render test only asserts the age text survives (`"8d"`).
- **golangci-lint in the verification** — applying the lesson from the v0.4.0 release (CI lint is the strict gate; `go vet`+`go test` miss it).
- **Type consistency:** `t.AgeHeat [4]lipgloss.Style`, `ageHeatLevel(time.Duration) int`, used consistently across T1–T2.
